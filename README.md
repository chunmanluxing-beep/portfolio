# 产品作品集 · 静态站

一个产品经理作品集单页,介绍「榴档期 · 旅拍自动化调度管理系统」这套真实运行的生产系统——它给谁用、两个端怎么分工、一条订单怎么走完、以及几个关键的产品决策。

## 这是什么

我在日本做旅拍业务,自建了一套覆盖「接单 → 建单 → 派单 → 拍摄 → 交付 → 结算」全链路的业务系统,由三个端协同:运营总控台(管理端)、摄影师移动端「榴档期 App」(iOS 已上架 App Store)、客人免登录交付页。

站点按**先总后分**组织:

- 先说给谁用(四类使用者),再说系统由哪两个入口构成
- 用一张「一条订单的完整旅程」把全站串起来,后面每一块能力都挂在这条线的某一段上
- 十二个能力板块**按归属分成三组**(管理端专属 / 两端共用 / 摄影师端专属),每张卡片可点开看图文详情
- 榴档期 App 的十二项差异化做成**图标 + 一句话**的网格,想看完整论证再点开
- 密度控制:九项机制留三条、七条优势留三条、四个决策只露标题与一句痛点一句结果,其余默认折叠但一条没删

## 可展开的图文详情

全站共 30 处原生 `<details>`,零 JavaScript:

- 十一张管理端能力卡(摄影师端 App 那块改为指向专章的指引卡,不重复展开)

## 二十三张配图全部由 CSS 绘制

11 张主配图 + 12 张板块机制图 + 12 个板块图标 + 12 个差异化图标 + 4 个角色图标,全部用 `div/span` + `flex/grid` + `border` + `border-radius` + 伪元素实现。不使用图片文件、图标字体、canvas 或 SVG,因此页面没有任何图片请求。

## 如何替换 Logo

导航栏与 Hero 各留了一个 Logo 占位(`.logoslot` 36×36、`.logoslot.big` 72×72,虚线框内写着 LOGO):

1. 把 logo 文件放进仓库根目录 `images/logo.png`(建议 512×512 透明底 PNG,深色底上要看得清)。
2. 把两处占位替换成 `img`:

```html
<!-- 替换前 -->
<span class="logoslot" aria-hidden="true">LOGO</span>
<!-- 替换后 -->
<img class="logoimg" src="images/logo.png" alt="榴档期">
```

3. 在 `style.css` 末尾补上尺寸:

```css
.logoimg      { display: block; width: 36px; height: 36px; border-radius: 9px; object-fit: contain; }
.logoimg.big  { width: 72px; height: 72px; border-radius: 16px; margin: 0 0 22px; }
```

Hero 那个记得加 `class="logoimg big"`。

## 如何替换截图占位

页面里预留了 **27 处**真实截图占位区(虚线框),去重后需要 **25 张图**。

> **完整清单见 [`images/README.md`](images/README.md)** ——每一处占位对应哪个文件名、放什么截图、在哪一屏、建议尺寸、必须打码什么,都列好了,并按优先级分成「第一优先 4 张 / 第二优先 6 张 / 其余 15 张」。页面上每个占位框的第二行也直接写着它对应的文件名。

### 批量替换(推荐)

1. 照着 `images/README.md` 的文件名,把打好码的截图放进仓库根目录的 `images/` 文件夹。
2. 放几张都行,不用凑齐,然后**告诉助手一句「images 里放了 X 张,替换一下」**。
3. 由助手统一把对应的占位块换成 `<img>` 并补上样式,**你不需要手改 HTML**。

### 手动替换(想自己动手时)

每一处占位该放哪张图、叫什么文件名,见 [`images/README.md`](images/README.md) 的三张分组表格,这里不再重复。

替换步骤:

1. **先打码**——截图里的客人姓名、电话、邮箱、金额、订单号等敏感信息必须先处理干净再入库。图片一旦提交到 Git 并推上 GitHub,历史记录里就会一直存在,删掉当前版本也没用。
2. 把处理好的图片按清单里的文件名放进 `images/` 文件夹(目录已经建好)。
3. 在 `index.html` 里找到对应的占位块,整块替换成 `img` 标签:

```html
<!-- 替换前(占位框第二行已经写好了它对应的文件名) -->
<div class="shot">
  <p class="shot-name">总控台订单列表页截图</p>
  <p class="shot-req">建议文件名:console-orders-list.png ｜ 建议 1600×900 ｜ 需打码:客人姓名、电话、金额</p>
</div>

<!-- 替换后 -->
<img class="shotimg" src="images/console-orders-list.png" alt="总控台订单列表页">
```

4. 如果想给图片加上和占位块一致的圆角与边框,在 `style.css` 末尾补一条:

```css
.shotimg { display: block; width: 100%; margin-top: 28px;
           border: 1px solid var(--line); border-radius: 12px; }
```

板块内的十二处占位(`class="shot shot-in"`)替换方式完全相同,只是尺寸更小,建议给 `img` 加上 `margin-top: 16px`。

占位块不替换也不影响观感——它本身是按设计元素处理的,留着即可。

仓库里的 `images/` 目录目前只有清单文件 `README.md` 与占位用的 `.gitkeep`,没有任何图片素材。

## 技术说明

```
index.html    单页全部内容(十屏 + 二十三张 CSS 配图 + 二十八个 CSS 图标)
style.css     暖色深色样式,响应式断点 1024px / 768px,含打印浅色适配
images/       截图目录:README.md 是 27 处占位的完整清单,.gitkeep 占位
.nojekyll     关闭 GitHub Pages 的 Jekyll 处理
```

- 零 JavaScript:平滑滚动由 CSS `scroll-behavior` 实现,板块展开由原生 `<details>` 实现
- 零外部资源:系统字体栈,无图片素材
- 支持打印导出 PDF

## 数据说明

页面中的业务数字均取自 2026-08 生产环境的只读查询,未做估算或推演。两处例外已在页面上明确标注口径:

- 建单流程对比中的耗时与人力,是 300 单规模下的实际运营口径;其中「2–4 分钟」只指**建单环节本身**,与派单侧的接单时长中位数 2.0 分钟是两个独立指标,不叠加。
- 人工介入次数对比图中的「≈ 15 次」与「≈ 4 次」为**示意口径**,按主要操作节点计数,用于体现结构差异,不是精确统计。
