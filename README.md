# 产品作品集 · 静态站

一个产品经理作品集单页,介绍「榴档期 · 旅拍自动化调度管理系统」这套真实运行的生产系统——它能做什么、自动化到什么程度、为什么这套模式比传统运转方式更好、以及几个关键的产品决策。

## 这是什么

我在日本做旅拍业务,自建了一套覆盖「接单 → 建单 → 派单 → 拍摄 → 交付 → 结算」全链路的业务系统,由三个端协同:运营总控台、摄影师移动端(iOS 已上架 App Store)、客人免登录交付页。

站点的重点是**系统能力**,而不是自我介绍:

- 十二个能力板块的全景(每块配一张纯 CSS 图标)
- 建单流程对比:传统模式六步 vs 榴档期三步
- 两个核心专章:智能派单调度系统、摄影师端 · 榴档期 App
- 与传统运转模式(微信群 + Excel + 客服记忆)的全链路对比
- 自动化程度与 AI 参与度:人工介入次数对比、自动化能力清单、AI 的边界
- 四个关键产品决策,含一次自己造成的事故复盘

## 八张配图 + 十二个板块图标全部由 CSS 绘制

不使用任何图片文件、不引外部资源、不用图标字体、不用 canvas。全部用 `div` + `flex/grid` + `border` + `border-radius` + 伪元素 + CSS 三角形实现,因此:

- 页面没有任何图片请求
- 深色适配与响应式天然一致
- 窄屏时横向流程图自动转为纵向

## 如何替换截图占位

页面里预留了 4 处真实截图占位区(虚线框),分别在:

| 位置 | 图名 | 建议尺寸 | 打码要求 |
| --- | --- | --- | --- |
| 第 2 屏 · 建单对比之后 | 总控台订单列表页 | 1600×900 | 客人姓名、电话、金额 |
| 第 3 屏 · 派单调度 | 发起抢单弹窗 | 1200×900 | 客人信息 |
| 第 4 屏 · 摄影师端 | 抢单大厅真机截图 | 750×1334 | 需同时出现可抢卡与灰卡 |
| 第 5 屏 · 模式优势 | 客人交付页 | 1200×900 | 客人姓名与金额 |

替换步骤:

1. **先打码**——截图里的客人姓名、电话、邮箱、金额、订单号等敏感信息必须先处理干净再入库。图片一旦提交到 Git 并推上 GitHub,历史记录里就会一直存在,删掉当前版本也没用。
2. 在仓库根目录新建 `images/` 文件夹,把处理好的图片放进去(例如 `images/orders.png`)。
3. 在 `index.html` 里找到对应的占位块,整块替换成 `img` 标签:

```html
<!-- 替换前 -->
<div class="shot">
  <p class="shot-name">总控台订单列表页截图</p>
  <p class="shot-req">建议 1600×900 ｜ 需打码:客人姓名、电话、金额</p>
</div>

<!-- 替换后 -->
<img class="shotimg" src="images/orders.png" alt="总控台订单列表页">
```

4. 如果想给图片加上和占位块一致的圆角与边框,在 `style.css` 末尾补一条:

```css
.shotimg { display: block; width: 100%; margin-top: 28px;
           border: 1px solid var(--line); border-radius: 12px; }
```

占位块不替换也不影响观感——它本身是按设计元素处理的,留着即可。

## 本地预览

不需要构建工具、不需要安装依赖:

```bash
open index.html                 # 直接打开
python3 -m http.server 8000     # 或起本地服务,访问 http://localhost:8000
```

## 技术说明

```
index.html    单页全部内容(八屏 + 八张 CSS 配图 + 十二个 CSS 图标)
style.css     深色样式,响应式断点 768px,含打印浅色适配
.nojekyll     关闭 GitHub Pages 的 Jekyll 处理
```

- 零 JavaScript:平滑滚动由 CSS `scroll-behavior` 实现
- 零外部资源:系统字体栈,无图片素材
- 支持打印导出 PDF

## 数据说明

页面中的业务数字均取自 2026-08 生产环境的只读查询,未做估算或推演。两处例外已在页面上明确标注口径:

- 建单流程对比中的耗时与人力,是 300 单规模下的实际运营口径;其中「2–4 分钟」只指**建单环节本身**,与派单侧的接单时长中位数 2.0 分钟是两个独立指标,不叠加。
- 人工介入次数对比图中的「≈ 15 次」与「≈ 4 次」为**示意口径**,按主要操作节点计数,用于体现结构差异,不是精确统计。
