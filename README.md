# 产品作品集 · 静态站

一个产品经理作品集单页,介绍「旅拍业务总控系统」这套真实运行的生产系统——它能做什么、为什么这套模式比传统运转方式更好、以及几个关键的产品决策。

## 这是什么

我在日本做旅拍业务,自建了一套覆盖「接单 → 建单 → 派单 → 拍摄 → 交付 → 结算」全链路的业务系统,由三个端协同:运营总控台、摄影师移动端(iOS 已上架 App Store)、客人免登录交付页。

站点的重点是**系统能力**,而不是自我介绍:

- 十二个能力板块的全景
- 两个核心专章:智能派单调度系统、摄影师端 App「榴档期」
- 与传统运转模式(微信群 + Excel + 客服记忆)的全链路对比
- 四个关键产品决策,含一次自己造成的事故复盘

## 页面结构(七屏)

```
1. Hero          一句话说清系统定位 + 四个核心数字
2. 系统全景      三端一条业务流(配图1)+ 十二个能力板块
3. 派单调度      派单模式对比(配图2)+ 九项机制 + 抢单动线(配图3)
4. 摄影师端 App  界面示意(配图4)+ 十二项差异化能力
5. 模式优势      八环节对比表 + 交付交接对比(配图5)+ 七条结构性优势
6. 产品决策      四个案例,含事故影响面图解(配图6)
7. 如何交付      无研发团队的人机协作方法论
```

## 六张配图全部由 CSS 绘制

不使用任何图片文件、不引外部资源、不用 canvas。全部用 `div` + `flex/grid` + `border` + CSS 三角形实现,因此:

- 页面总大小约 65KB,加载没有任何图片请求
- 深色/浅色适配与响应式天然一致
- 窄屏时横向流程图自动转为纵向

## 本地预览

不需要构建工具、不需要安装依赖:

```bash
open index.html                 # 直接打开
python3 -m http.server 8000     # 或起本地服务,访问 http://localhost:8000
```

## 技术说明

```
index.html    单页全部内容(七屏 + 六张 CSS 配图)
style.css     深色样式,响应式断点 768px,含打印浅色适配
.nojekyll     关闭 GitHub Pages 的 Jekyll 处理
```

- 零 JavaScript:平滑滚动由 CSS `scroll-behavior` 实现
- 零外部资源:系统字体栈,无图片素材
- 支持打印导出 PDF
